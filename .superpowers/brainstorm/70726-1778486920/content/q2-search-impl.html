Textsuche — wo passiert das Filtern?

Durchsucht: Titel + Logline

A — Clientseitig (empfohlen für MVP)
Alle Projekte werden geladen, Filterung passiert im Browser per toLowerCase().includes(). Keine DB-Änderung. Sofortige Reaktion beim Tippen. Limitierung: skaliert nicht bei 1000+ Projekten — aktuell kein Problem.
B — Serverseitig via Supabase ilike
Suchanfrage geht per URL-Param an den Server, Supabase filtert mit .ilike('title', '%query%'). Skalierbar, aber ~300ms Latenz pro Keystroke (braucht Debounce). Kein Full-Text-Index nötig.
C — Serverseitig via Postgres Full-Text Search
DB-Migration: tsvector Column + GIN-Index. Relevanz-Ranking möglich. Aufwändigste Option, macht erst Sinn ab hunderten Projekten.
